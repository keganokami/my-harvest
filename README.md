# 🌱 my-harvest — 家庭菜園プランナー

小さな畑（畝2本程度）で家庭菜園を始めるための、年間計画・作付けシミュレーション・栽培アドバイスの Web アプリ。

### 👉 **https://keganokami.github.io/my-harvest/**

スマートフォンでそのまま使えます（Safari で開く → 共有 → 「ホーム画面に追加」でアプリのように起動します）。

**対象：栽培区分「中間地」／ 北摂丘陵・標高約200m の内陸を想定（平野部より1〜2℃低い前提で補正）**
**露地（畑）専用**です。ベランダ・プランター栽培は扱いません。

---

## できること

このアプリが答えるのは3つのことです。**何を育てるか / どう育てるか / 今と直近どうすればよいか。**
スマートフォンでの利用を前提に作っています（画面下部のタブで移動、ホーム画面に追加して使えます）。

| タブ | 答えること | 内容 |
|---|---|---|
| **📍 いま** | 今と直近どうすればよいか | 今週やることのチェックリスト（登録した栽培の作業＋適期が終わりそうな種まき＋買い物）、育てているものの診断、いま植えられるもの、今月の作業（折りたたみ） |
| **🌱 育てる** | 何を育てるか／どう育てるか | 分類・難易度・時期で絞り込む野菜図鑑。詳細に作型ごとの年間の帯グラフ、育て方、水やり、肥料、株間、収量、トラブル対処 |
| **🧮 プラン** | 何を育てるか（畝の割り当て） | 敷地の寸法から畝の本数と長さを算出し、「株間×条数」で畝を何cm使うか計算。畝の長さ・栽培期間の重なり・連作障害を自動検証。畑の平面図と収穫の見込みを表示。おまかせ年間プランの自動生成 |
| **📒 記録** | 今どうすればよいか | 栽培日誌。今の状態と作業を記録すると診断が出る。収穫量の累計、JSON書き出し／読み込み |
| **🔎 調べる** | どう育てるか | 症状から原因を辿る診断、土づくり・輪作・種と苗の選び方などの基礎知識 |

年間カレンダー（全作型のガントチャート）は「育てる」タブの折りたたみに入れてあります。
日常的に見るのは各野菜の詳細にある**年間の帯グラフ**（1年を1本の帯で表示）のほうです。

### 今週やること

「いま」タブの先頭に出るチェックリストが、このアプリの中心です。次の3つを1本にまとめています。

- 登録した栽培の診断のうち、**急ぐもの**（防虫ネットが未記録、追肥時期、霜が近い、など）
- **適期の終わりが1ヶ月以内**に迫っている種まき・植付け（「ダイコンの種まきは9月下旬まで — あと約30日」）
- その月に**買っておくもの**（人気の苗と種は売り切れるため）

チェックは旬（10日）ごとに自動でリセットされます。

## 「今の状態を入力 → 診断」のしくみ

「わが家の記録」タブで栽培を登録し、**記録を追加**から今の状態を入力します。

| 入力項目 | 例 |
|---|---|
| 生育ステージ | 発芽した／本葉2〜3枚／花が咲いた／収穫が始まった …（分類ごとに用意） |
| 株の様子 | がっしり／ふつう／ひょろ長い／小さいまま |
| 葉の色 | 濃い緑／ふつう／薄い・黄色っぽい／斑点がある |
| 気になること | 葉に穴・小さな虫・白い粉・しおれる・実がつかない など14項目 |
| 今日やった作業 | 水やり／追肥／間引き／防虫ネット／わき芽かき／土寄せ など11項目 |
| 収穫量・メモ | 30個、など |

これを次の7つの観点で診断します。

1. **生育の遅れ** — 経過日数から標準ステージを算出し、記録と比較。遅れていれば日照・肥料・間引き・気温のどれが原因かを絞り込む
2. **ステージ固有の作業** — 発芽期なら間引きと防虫、開花期なら追肥開始と人工授粉、収穫期なら穫り方
3. **見た目からの推定** — 徒長／肥料切れ／窒素過多／根腐れの切り分け
4. **症状からの特定** — その野菜固有のトラブル（例：ミニトマトの尻腐れ果）を優先し、なければ一般的な原因を提示
5. **作業の抜け** — 防虫ネット未記録、追肥間隔超過、わき芽かき放置、夏場の水やり途絶
6. **季節リスク** — 霜・猛暑・台風・梅雨を、その作物と場所に関係する場合だけ警告
7. **次の作業** — 2ヶ月以内に来る工程だけを予告（終盤の株には片付けと次作の提案に切り替わる）

作業記録は「最後に追肥した日」「最後に水やりした日」として自動で参照されるので、チェックを入れておくほど診断が正確になります。

## 作付けプランは「畝」単位で計算します

抽象的な「区画◯m²」ではなく、実際に畑で作る**畝（うね）**を単位にしています。

**① 敷地の4辺 → 畝の構成を自動計算**

敷地は**長方形とは限らない**ので、4辺の実測値（cm）を入力します。
左辺を垂直に固定し、2円の交点として右下の頂点を求めて四角形を確定させます。

```
上辺110cm / 下辺140cm / 左辺160cm / 右辺140cm
  → 頂点 (0,0) (110,0) (138,137) (0,160)  面積 1.86m²（約1.1畳）
```

畝は「畝幅＋通路幅」で並べ、**帯が敷地に収まる範囲を畝の長さ**とします
（帯の左右両端で敷地の上端・下端を取り、その共通部分）。
辺が斜めなので **畝ごとに長さが変わります**。

```
南北 / 畝50cm / 通路なし  → 畝1: 50×152cm、畝2: 50×143cm  栽培面積 1.48m²
```

畝の向き（南北／東西）も選べます。小さく不整形な敷地では、向きと畝幅の
組み合わせで栽培面積が 1.0〜1.6m² と大きく変わるため、
**「畝の取り方の候補」を栽培面積の大きい順に提示**し、タップで切り替えられます。

成立しない寸法（1辺が他の3辺の合計より長いなど）は検出して警告します。

**② 作物ごとに「条数」と「必要な畝の長さ」を計算**

畝幅から何条植えられるかを条間で決め、株間から必要な長さを出します（畝の両肩に10cmずつ余裕を取ります）。

```
条数     = floor((畝幅 - 20) ÷ 条間) + 1
必要長さ = ceil(株数 ÷ 条数) × 株間
```

実例（畝幅70cm）:

| 野菜 | 株間 / 条間 | 条数 | 30株に必要な長さ |
|---|---|---|---|
| コマツナ | 5 / 15cm | 4条 | 40cm |
| ニンニク | 15 / 20cm | 3条 | 150cm |
| ダイコン | 25 / 30cm | 2条 | 375cm（畝1本に収まらない） |
| ブロッコリー | 45 / 45cm | 2条 | 675cm（同上） |
| ミニトマト | 45 / 70cm | 1条 | 1350cm（同上） |

**③ 割り当ての編集**

畝の割り当ては、各行をタップするとその場で直せます。

- **作型**（種から／苗から、春まき／秋まきなど）の変更
- **畝**の移動
- **株数**の増減（−10／−1／直接入力／＋1／＋10）。畝の何cmを使うかが即座に更新され、はみ出す株数なら警告が出ます
- **並び替え**（↑前へ／↓後ろへ）。並び順は畝の先頭からの配置順なので、平面図の配置がそのまま変わります
- 削除

「記録」タブの栽培も、作型・開始日・株数を後から直せます。

**④ 検証**

- **畝の長さ** — 各旬（10日）ごとに、その畝を使う作物の長さを合計して超過を検出
- **連作障害** — 同じ畝に同じ科が入っていないか
- **同居** — 同時に3種以上が同居する畝は、日照の影について注意を出す
- **空き** — 年間で長く空く畝には短期作物の追加を提案

**⑤ 畝幅を変えると何株植えられるか**

条数は畝幅と条間で決まるため、畝を広げると同じ長さでより多く植えられます。
野菜を選ぶと、畝幅ごとの条数と株数が比較表で出ます（コマツナ・畝270cmの例）。

| 畝幅 | 60cm | **70cm** | 90cm | 120cm |
|---|---|---|---|---|
| 条数 | 3条 | **4条** | 5条 | 7条 |
| 畝1本(270cm) | 162株 | **216株** | 270株 | 378株 |

条間の広い作物（ミニトマト・キュウリ）は畝を広げても条数が増えないので、
「畝を広くする意味があるかどうか」が作物ごとに分かります。野菜図鑑の詳細にも同じ表があります。

**⑥ 畑の平面図**

畝・通路・株の位置を実寸で描いた上から見た図を表示します。

- 敷地の四角形そのもの（斜めの辺もそのまま）と、4辺の実測値
- 畝の矩形と、通路・敷地の余り（ハッチング）
- 各作物が畝の何cmから何cmを占めるか
- **1株ずつを点で描画**（条の位置と株間が実際の間隔で並びます）
- 北の向き、50cmごとの目盛り、空いている長さ
- 畝からはみ出す作付けは赤い破線で警告

**時期スライダー**で36旬のどの時点でも表示でき、年間を通して畑がどう変わるかを確認できます。

## データの保存について（DB は今のところ不要）

記録はブラウザの `localStorage` に保存されます。1人・1端末で使う分にはこれで十分で、サーバーも DB も要りません。
消失に備えて、記録タブの **「記録を書き出す（JSON）」** でファイルに保存できます。別の端末やブラウザでは「読み込む」で復元できます。

サーバー＋DB（Next.js など）が必要になるのは次のいずれかが出てきたときです。

- スマホと PC で同じ記録を見たい（同期）
- 写真を継続的に貯めたい（localStorage は約5MBが上限）
- 家族と記録を共有したい
- 複数年のデータを横断して分析したい

書き出した JSON がそのまま移行データになる形にしてあるので、その時点で移せます。

GitHub Pages は `cache-control: max-age=600` を返すため、ブラウザが古い JS を

CSS/JS の参照に `?v=<タイムスタンプ>` を付けており、`tools/release.sh` が
デプロイのたびに打ち直します。

**いま見ている版はフッターの `build ...` で確認できます。** これが最新でなければ、
ページを再読み込み（iOS Safari は共有 →「リロードを要求」、

デプロイの状態は次でも確認できます。


> 公開リポジトリなので、**個人が特定できる情報（住所・氏名・メールアドレス）を書き込まない**ようにしてください。

すべて素の HTML / CSS / JavaScript（ES5相当）で、ビルドツールも外部ライブラリも使っていません。
データはブラウザの `localStorage` にのみ保存され、外部には一切送信されません。

### スマホ対応の方針

- **モバイルファースト**：基本のスタイルがスマホ向けで、760px 以上で PC 表示に切り替わります
- タブは画面**下部に固定**（親指で届く位置）。PC では上部のタブバーになります
- 入力欄は `font-size:16px`（これ未満だと iOS が勝手にズームします）、タップ領域は最低 44px
- 詳細画面はスマホでは**全画面シート**、PC では中央のモーダル
- 横に広い表（年間カレンダー・収支）は個別に横スクロールし、**ページ全体は横に動きません**
- `apple-touch-icon` と `apple-mobile-web-app-capable` を設定済み。ホーム画面に追加するとアプリのように開きます
- 幅360pxでの実測で、意図した横スクロール要素以外にはみ出しゼロを確認しています

## データの考え方

### おすすめの優先順位（重み付け）

作付けの提案は次の重みで並びます。

1. **失敗しにくさ**（最重視・×3.0） — 発芽率、病害虫の付きにくさ、管理のシビアさ
2. **その作型自体の難易度**（×2.0） — 同じ野菜でも「苗から」は易しく「種から」は難しい
3. **食費への貢献**（×2.0） — 面積あたりの金額効率、保存の効きやすさ
4. **採れたての価値**（×1.0） — エダマメ・ソラマメのように市販品と別物になるもの
5. **収穫期間の長さ** — 長く穫れるほど加点（畑を空けない）
6. **マメ科ボーナス** — 根粒菌で土が肥えるため、輪作上の価値を加点

### 日付の精度

日付は**旬（上旬・中旬・下旬）単位**で、種苗メーカーの中間地向け作型表に基づく一般的な目安です。
実際の作業は、その年の天候、購入した種袋の記載、品種特性に合わせて調整してください。

想定している立地は平野部の市街地より 1〜2℃ 低く、遅霜が4月上旬まであるため、**春の夏野菜の定植は市街地より1週間ほど遅らせる**のが安全です（アプリ内でも注意表示が出ます）。

### 収量の目安について

収量はスーパーで売られている単位（本・個・株・kg）に揃えた概算で、栽培が順調にいった場合の目安です。
品種・天候・管理でかなり変わるので、あくまで「どれくらい穫れるか」の見当をつけるためのものです。

**収支や節約額の試算は意図的に入れていません。** 家庭菜園はお金を稼ぐためのものではないためです。
ただし「買うと高いのに作るのは簡単」（ルッコラ・エダマメ・ソラマメ・ニンニクなど）は
育てる野菜を選ぶうえで重要な観点なので、各野菜の **おトク度（★1〜5）** として残し、
おすすめの並び順に反映しています。

## 野菜を追加・修正する

`data/veg-*.js` に同じ形式のオブジェクトを追加するだけです。

```js
{
  id: 'unique-id', name: '表示名', family: 'アブラナ科', emoji: '🥬',
  category: '葉物',
  difficulty: 1,      // 1（易）〜5（難）
  beginner: 5,        // 失敗しにくさ 1〜5
  cost: 3,            // 食費への貢献 1〜5
  freshness: 3,       // 採れたての価値 1〜5
  speed: 5,           // 収穫までの早さ 1〜5
  place: ['plot'],    // 栽培場所（現在は畑のみ）
  sun: 'half',        // full（日なた必須）／ half（半日陰でも可）／ shade（半日陰向き）
  depth: 15,          // 必要な土の深さ cm
  spacing: { plant: 5, row: 15 },   // 株間・条間 cm
  perM2: 100,         // 1m²あたりの株数

  }],

}
```

`kind` は `sow`（種まき）/ `nursery`（育苗）/ `plant`（植付け）/ `grow`（生育）/ `harvest`（収穫）/ `store`（貯蔵）。
`to` が `from` より前の月なら年をまたぐ範囲として扱われます（例：`from: [11,1], to: [6,2]` ＝ 11月上旬〜翌6月中旬）。

新しい科を追加する場合は `js/core.js` の `FAMILY_INFO` にも連作年数を追加してください。
